## 背景

在 2026 年 CEEES 深度学习周的黑客松中，我和团队开发了 **HaLoop**——一个安全的人类管控 AI 编程助手。项目的核心理念是：**AI 可以辅助编程，但关键决策必须由人类掌控**。

## 问题定义

AI 编程助手（如 GitHub Copilot、Cursor 等）可以极大地提高开发效率，但它们也带来了安全隐患：

- 直接修改敏感路径（认证模块、数据库迁移、依赖文件）
- 生成可能包含安全漏洞的代码
- 缺乏问责机制——谁批准了 AI 的修改？

我们的解决方案是在 AI 和代码库之间加入一个**治理层**。

## 技术架构

我们设计了一个三层架构：

1. **IDE 层**：VS Code 扩展，集成在开发者日常工作流中
2. **治理层**：Next.js 仪表盘，提供审批、策略、审计功能
3. **持久层**：SQLite（Demo）/ PostgreSQL（生产）

### 关键设计决策

**双重风险评估**：我们在后端（AI 生成方案时）和前端（方案返回后）各做一次风险评估，取两者最高值作为最终风险等级。这避免了单点误判。

**SSE + 轮询双通道**：审批决策的传播同时使用 Server-Sent Events 和 HTTP 轮询，确保在网络不稳定的情况下也能及时收到决策。

**死者开关**：所有 AI 修改的文件都被记录在 Session Manifest 中，出了问题可以一键回滚。

## 经验教训

1. **先设计合约再写实现**：API 契约（请求/响应格式）应该是最先确定的，它指导了前后端的并行开发
2. **Demo 模式很关键**：评委需要在没有完整基础设施的情况下运行项目，SQLite + JSON 的 Demo 模式让项目开箱即用
3. **产品思维**：技术好只是基础，如何让评委快速理解你的价值主张同样重要

## 结语

Hackathon 不仅仅是一场比赛，更是一次快速学习和验证想法的机会。如果你有想法，就去实现它！
